# 截图选区与编辑器无闪交接设计

## 目标

消除用户完成截图框选后、原位编辑器出现前的屏幕闪烁，并降低鼠标松开后的截图等待时间。鼠标松开到编辑器可交互期间必须保持连续画面，不出现裸桌面、遮罩亮度突变、重复蓝色边框或选区边缘位移。

现有产品行为保持不变：

- 顶部模式控件默认选择截图，框选完成后直接执行，不增加二次确认；
- 截图继续使用 ScreenCaptureKit，并排除 MacTools 自身窗口；
- 编辑器继续在原选区位置展示，支持现有标注、撤销、完成和取消操作；
- 录屏继续在框选完成后启动，不改变输出格式、保存位置或控制条行为。

## 现状与根因

`ScreenSelectionOverlayController` 在收到有效选区后立即执行 `dismiss()`，关闭所有选区面板，再把选区交给 `ScreenCaptureCoordinator`。协调器随后异步等待 `SCScreenshotManager.captureImage`，取得图像后才由 `ScreenshotEditorPanelController` 创建并置前新的全屏编辑面板。

当前 41 次运行记录中的静态抓图耗时如下：

| 指标 | 耗时 |
| --- | ---: |
| 最小值 | `17 ms` |
| 中位数 | `64 ms` |
| P90 | `208 ms` |
| P95 | `223 ms` |
| 最大值 | `402 ms` |
| 平均值 | `96.5 ms` |

这段异步等待时间内没有任何 MacTools 面板覆盖桌面，因此用户会看到：

`选区遮罩 → 裸桌面 → 编辑遮罩与截图`

编辑器展示时还会执行 `NSApp.activate(ignoringOtherApps: true)` 和 `makeKey()`。如果窗口交接跨越不同的 WindowServer 显示批次，原应用焦点变化会进一步强化闪烁。

选区边缘还存在次要的位置差异：拖动层使用原始浮点矩形绘制，抓图和编辑器使用 `ScreenCaptureSelection.frame` 的 `.integral` 矩形。两者边缘最多相差不足 `1 pt`，在 Retina 屏幕上可能表现为约两个物理像素的跳动。

状态机只允许一次有效选区进入截图阶段，运行记录也只出现一次抓图和一次编辑器展示；问题不是截图会话重复启动。

## 方案比较

| 方案 | 优点 | 代价与边界 |
| --- | --- | --- |
| 保留选区层并进行两阶段窗口交接（采用） | 不暴露裸桌面；改动集中在现有三个控制器；继续沿用选区窗口与编辑窗口的焦点边界 | 需要锁定已提交选区，并保证编辑器首帧准备、置前和旧面板关闭的顺序 |
| 选区与编辑器复用同一个 `NSPanel` | 理论上不存在跨窗口空档 | 需要重构 `.nonactivatingPanel`、`canBecomeKey` 和应用激活策略，容易破坏框选时不抢焦点及编辑器快捷键 |
| 仅优化抓图耗时或添加淡入淡出 | 实现范围较小 | 无法覆盖 ScreenCaptureKit 冷路径；淡入淡出仍会显示错误的中间画面，只能弱化而不能消除闪烁 |

## 当前方案

采用“保留选区层、预备编辑器、同批次交接”的两阶段展示策略。

### 选区提交

有效选区完成时，`ScreenSelectionOverlayController` 不再立即调用 `dismiss()`，而是进入已提交状态：

1. 保存当前截图或录屏模式；
2. 锁定所有 `ScreenSelectionView`，忽略后续鼠标按下、拖动和松开事件；
3. 保持现有遮罩、选区和顶部模式控件的视觉状态不变；
4. 只向协调器提交一次选区；
5. 保留 Escape 取消能力。

已提交状态不新增进度动画，也不改变遮罩透明度，避免在抓图等待期制造新的视觉跳变。

### 截图等待

`ScreenCaptureCoordinator` 在选区层仍可见时调用 `captureStill(for:)`。`SystemScreenCaptureService` 继续按进程和 bundle identifier 排除 MacTools，因此保留的选区面板、模式控件和边框不会进入截图。

截图成功后，协调器先要求 `ScreenshotEditorPanelController` 准备隐藏的编辑面板。准备阶段完成以下工作，但不改变窗口顺序：

- 创建 `ScreenshotEditorView` 和 `NSHostingView`；
- 设置全屏面板、截图画布及工具条位置；
- 执行必要的 AppKit/SwiftUI 布局和首次绘制准备；
- 保持面板不可见，不提前激活 MacTools。

### 抓图性能优化

无闪交接保证任意实际耗时下的画面连续性；抓图性能优化用于缩短用户等待，两者分别验证，不用缩短遮罩保留时间掩盖性能问题。

#### 分段计时

现有 `screen capture still image ready` 只记录 `captureStill(for:)` 的聚合耗时，无法区分内容准备、过滤器配置和系统抓帧。协调器和采集服务增加以下非敏感计时：

| 阶段 | 起止边界 |
| --- | --- |
| 预热等待 | 请求 `shareableContent` 到获得当前缓存或加载结果 |
| 捕获源准备 | 查找显示器、构造应用排除列表、`SCContentFilter` 和 `SCStreamConfiguration` |
| 系统抓帧 | 调用 `SCScreenshotManager.captureImage` 到返回 `CGImage` |
| 编辑器准备 | 创建隐藏面板到完成首次布局和绘制准备 |
| 窗口交接 | 开始激活 MacTools 到编辑器成为 key window |
| 用户感知总耗时 | 有效 `mouseUp` 到编辑器可交互 |

日志只记录阶段名称、耗时和成功或失败状态，不记录选区坐标、窗口标题、截图内容、显示器名称或图像字节。

#### 短期预热缓存

`ScreenCapturePreparationCache` 当前只在单次会话中复用加载任务，而协调器会在每次开始、完成或取消时立即使缓存失效。调整为以下短期复用策略：

- `SCShareableContent` 成功结果在内存中保留 `5 秒`；
- 新会话在有效期内直接复用结果，不重复查询屏幕和应用拓扑；
- 缓存过期后由新的截图入口立即启动后台刷新，选区交互继续展示；
- 正常完成和用户取消不再无条件清空缓存；
- 收到系统屏幕参数变化通知时立即失效，避免沿用分辨率、缩放比例或显示器排列已经变化的拓扑；
- 内容查询错误或找不到目标 `displayID` 时立即失效，并使用最新内容重试一次；
- 权限错误立即失效并进入现有权限错误处理，不执行无意义的同会话重试；
- 单次重试仍失败时进入现有错误处理，不循环重试；
- 缓存不写入磁盘，也不跨应用进程保留。

该策略主要优化连续截图和用户快速框选时的准备等待。系统单次抓帧仍由 ScreenCaptureKit 控制，不能用缓存承诺固定最大耗时。

#### 性能预算

首轮实现使用至少 50 次打包应用截图建立新基线，其中包含首次启动后的冷截图、连续热截图、大选区、屏幕边缘和多显示器：

| 指标 | 目标 |
| --- | ---: |
| 有效 `mouseUp` 到取得 `CGImage` 的 P50 | `≤ 50 ms` |
| 有效 `mouseUp` 到取得 `CGImage` 的 P95 | `≤ 150 ms` |
| 有效 `mouseUp` 到编辑器可交互的 P95 | `≤ 200 ms` |

WindowServer 和 ScreenCaptureKit 的尾部延迟不受应用完全控制，因此不设置单次最大耗时成功条件。任何超出预算的样本仍必须满足无闪交接要求。

#### 第二阶段触发条件

如果短期缓存完成后，分段数据证明“系统抓帧”阶段仍使取得 `CGImage` 的 P95 高于 `150 ms`，再单独评估基于临时 `SCStream` 的低延迟路径：

1. 在 `mouseDown` 确定起始显示器后启动该显示器的临时流；
2. 拖动期间保留最新完整帧，不为未参与框选的显示器创建流；
3. `mouseUp` 后使用时间戳不早于提交时刻的首个完整帧，并按归一化选区裁切；
4. 取得图像或取消后立即停止临时流；
5. 流未及时产出有效帧时回退到 `SCScreenshotManager.captureImage`。

临时流会增加显存、能耗、帧同步和资源清理复杂度，不进入首轮实现，也不能通过降低 Retina 输出分辨率换取速度。

### 无动画交接

编辑器首帧准备完成后，在 `MainActor` 的同一次同步显示提交中按以下顺序交接：

1. 激活 MacTools；
2. 将已准备的编辑面板置于选区面板之上；
3. 确认编辑面板已接受展示；
4. 立即关闭全部选区面板；
5. 让编辑面板成为 key window。

交接过程不使用延迟、淡入淡出或窗口缩放动画。旧选区层只有在新编辑器已经置前后才退出，因此 ScreenCaptureKit 耗时不会形成可见空档；窗口顺序变更也不会留下稳定的双层遮罩状态。

如果编辑面板未能成功展示，协调器保留现有失败处理：清理选区层和编辑器，结束会话并显示错误提示，不将会话留在锁定状态。

### 录屏边界

截图与录屏共用选区提交逻辑。录屏模式下同样先保持已锁定的选区层，待 `recorder.start` 成功后再关闭选区层并展示录制控制条。

MacTools 已从 ScreenCaptureKit 内容过滤器中排除，因此等待录制启动期间保留选区层不会进入视频。录制启动失败时沿用统一失败处理并清理选区层。

## 坐标一致性

选区拖动、提交、ScreenCaptureKit `sourceRect` 和编辑器布局统一以 `ScreenCaptureSelection` 归一化后的显示器相对矩形为准。

- 拖动绘制矩形在当前显示器内标准化并对齐到现有整数点策略；
- `mouseUp` 保存的完成矩形使用同一归一化结果；
- 编辑器不再从另一份原始浮点矩形重新计算位置；
- 多显示器仍以起始显示器的 `displayFrame` 和 `displayID` 为坐标边界。

该约束消除选区边框与编辑器画布之间不足 `1 pt` 的位置和尺寸变化，同时保持现有反向拖动、显示器边界裁切和最小选区规则。

## 组件边界

| 组件 | 职责变化 |
| --- | --- |
| `ScreenSelectionOverlayController` | 管理选区未提交、已提交和关闭状态；提交后锁定交互但保持画面；由协调器决定最终关闭时机 |
| `ScreenCaptureCoordinator` | 负责抓图或录屏启动期间的选区层生命周期，并编排编辑器准备、窗口交接、取消和失败清理 |
| `ScreenshotEditorPanelController` | 将现有一次性 `present` 拆分为隐藏准备与正式展示两个阶段；展示前完成布局，展示后保持现有复制和取消回调 |
| `ScreenCaptureSelection` | 继续作为唯一的选区归一化与坐标转换来源，不引入另一套窗口坐标模型 |
| `ScreenCapturePreparationCache` | 为成功结果增加带时钟注入的 `5 秒` 有效期，并保留现有并发任务复用和 generation 保护 |
| `SystemScreenCaptureService` | 保持当前 MacTools 应用排除和截图分辨率策略；记录内容准备、捕获源构造和系统抓帧耗时；响应屏幕参数变化；在内容查询错误或显示器缺失时刷新并重试一次 |

不把 AppKit 窗口控制下沉到 `MacToolsCore`，也不为本次交接引入通用窗口框架。

## 取消与异常处理

- 抓图等待期间按 Escape：立即关闭选区层并把会话切换为取消；异步抓图即使稍后返回，也必须通过状态检查丢弃结果，不得再展示编辑器。
- 重复鼠标事件或快捷键：已提交选区不再产生第二次 `onSelection`；协调器现有会话互斥继续拒绝新的截图入口。
- 抓图失败：关闭选区层，清理预备中的编辑器和缓存，再显示现有屏幕采集失败提示。
- 编辑器准备或展示失败：不得先关闭选区层再尝试恢复；统一进入失败清理。
- 录屏启动失败：关闭选区层和控制条，删除或封口行为继续由现有录制器错误路径负责。

## 测试与验证

### 自动测试

- 增加选区提交生命周期测试，验证有效选区只提交一次，提交后保持展示并拒绝后续拖动，取消或显式关闭后恢复干净状态。
- 增加窗口交接顺序测试或源契约测试，验证编辑器先准备和置前，选区层后关闭，且交接路径不包含固定延迟或淡入淡出。
- 增加取消竞争测试：抓图返回前取消会话，返回后不得进入编辑状态或展示编辑器。
- 扩充 `ScreenCaptureSelectionTests`，覆盖小数坐标、反向拖动和显示器边缘裁切，验证选区绘制、抓图源矩形与编辑器矩形使用同一归一化结果。
- 扩充 `ScreenCapturePreparationCacheTests`，使用注入时钟验证 `5 秒` 内复用、到期刷新、显式失效、并发请求合并和旧代际结果隔离。
- 增加采集服务测试，验证目标显示器缺失时只刷新并重试一次，第二次失败后返回原有错误。
- 验证阶段计时日志不包含选区坐标、窗口标题、图像数据或其他屏幕内容。
- 运行聚焦测试后运行完整 `swift test`。

### 打包应用验证

使用 `scripts/rebuild_and_run_app.sh` 构建并启动打包应用，在明暗对比明显的静态页面上验证：

1. 冷、热状态下分别连续截图，覆盖日志中超过 `200 ms` 的抓图等待；
2. 录制屏幕并逐帧检查鼠标松开到编辑器可交互的过程；
3. 确认没有裸桌面、整屏亮度突变、双层遮罩、重复蓝框或选区边缘位移；
4. 确认编辑器每次出现后可立即使用 Escape、Command+Z 和 Command+Return；
5. 覆盖正向与反向拖动、小选区、大选区、屏幕边缘和多显示器；
6. 抓图等待期间按 Escape，确认编辑器不会延迟出现；
7. 验证截图中不包含选区遮罩、顶部模式控件或编辑器窗口；
8. 验证录屏启动过程不闪烁，选区层和控制条不进入 MP4；
9. 完成至少 50 次冷、热状态混合截图，汇总分段 P50、P95 和最大值，并与现有基线及性能预算比较；
10. 连续截图间隔小于和大于 `5 秒`，确认缓存分别命中和刷新；插拔显示器或切换显示配置后确认不会使用过期显示器拓扑。

## 成功标准

- 任意实际抓图耗时下，鼠标松开到编辑器首帧之间始终有正确的 MacTools 表面覆盖屏幕；
- 逐帧检查不出现裸桌面、亮度闪烁、重复遮罩或选区位置跳动；
- 至少 50 次打包应用截图的新基线达到取得 `CGImage` 的 `P50 ≤ 50 ms`、`P95 ≤ 150 ms`，以及编辑器可交互的 `P95 ≤ 200 ms`；
- 阶段数据未达预算时必须指出具体瓶颈；只有系统抓帧阶段仍超过预算才进入临时 `SCStream` 方案评估；
- 不增加二次确认、固定等待时间或过渡动画；
- 截图、录屏、取消、错误处理和键盘快捷键保持现有产品约定；
- 首轮改动仅涉及截图选区、协调器、编辑器展示、短期预热缓存、阶段计时及对应测试和人工验证清单。
