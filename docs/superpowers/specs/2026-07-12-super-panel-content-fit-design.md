# 超级右键文件动作统一与完整展示设计

## 目标

统一已选择文件和文件夹时的超级右键行为，并让标准窗口布局列表在面板内一次完整展示，不再因为当前过小的高度出现滚动条。

## 场景规则

### 已选择文件、文件夹或图片文件

- 文件、文件夹和图片文件使用完全相同的动作集合。
- 第一项固定为「复制文件路径」。
- 后续展示当前配置的全部窗口布局按钮。
- 不再为已选择的文件夹展示「新建文件」「复制当前路径」或「在终端打开」。
- 文件夹仍使用文件夹图标和「文件夹」预览标签，只统一动作，不抹平内容类型展示。

### Finder 空白处

- 保留现有目录动作：「新建文件」「复制当前路径」「在终端打开」。
- 在目录动作后继续展示窗口布局列表。
- 该场景与“已选择一个文件夹”保持区分，因为它操作的是 Finder 当前目录本身。

### 其他场景

- 普通应用未选择文本时仍只展示窗口布局列表。
- 选择文本或 URL 时仍展示文本处理内容，不增加窗口布局。

## 面板尺寸与滚动策略

- 文件系统和纯窗口布局面板的基准宽度从 260 点增加到 320 点，继续使用两列布局按钮。
- 面板高度根据预览行、主要动作行、布局标题和布局按钮行数动态计算。
- 标准 8 个窗口布局按钮必须全部显示，不出现垂直滚动条或裁切。
- 文件/文件夹场景需要同时完整显示预览、一个「复制文件路径」动作和标准布局列表。
- Finder 空白处需要同时完整显示预览、三个目录动作和标准布局列表。
- 当用户配置的自定义布局数量异常多、完整高度超过屏幕可用区域时，才保留滚动作为安全降级；面板定位继续限制在当前屏幕可见区域内。

## 视觉方向

- 延续现有 Liquid Glass 材质、圆角、双列网格和系统蓝强调色，不重新设计控件风格。
- 主要焦点是“当前上下文动作”，窗口布局作为紧随其后的空间操作区。
- 采用内容自适应高度，避免固定大面板在布局数量较少时留下大片空白。
- 保持 8 点间距体系、现有按钮命中区域和文字层级。

## 灰边与窗口外壳约束

- `NSPanel` 继续使用无标题栏的 borderless/nonactivating 样式。
- 禁止恢复系统窗口阴影。
- hosting view 和 frame view 继续使用透明背景、连续圆角和 backing-layer 裁切。
- UI 验证必须在真实运行面板上检查四周，不允许出现额外灰色矩形边框、标题栏残留、系统阴影或圆角外的 backing layer。

## 测试与验收

- 内容测试：文件、文件夹、图片文件均生成「复制文件路径」加布局按钮。
- 回归测试：Finder 空白目录动作仍为三项加布局按钮。
- 尺寸测试：标准 8 个布局按钮在纯布局、已选文件和 Finder 当前目录三种内容下均能获得足够高度。
- 视图测试：标准内容高度不需要滚动；超出屏幕安全上限时仍允许滚动。
- 全量运行 `swift test`。
- 运行 `scripts/rebuild_and_run_app.sh`，真实触发超级右键并截图检查完整内容与灰边。

## 非目标

- 不修改窗口布局按钮的具体动作、顺序或用户配置。
- 不改变文本翻译、文本悬浮中转逻辑。
- 不删除仍供 Finder 空白目录场景使用的文件创建和终端动作能力。
