# MacTools 性能风险治理设计

## 文档状态

- 状态：方案已确认，待实施
- 代码基线：`bd9bf17`
- 目标分支：`ai/performance-risk-hardening`
- 实施顺序：P1 全部修复并完成完整自测后，再实施 P2

## 目标与边界

当前方案治理已确认可能造成界面假死、整机资源压力或长期性能退化的风险，同时保持以下产品语义：

- 剪贴板继续按“文件 URL、非空文本、图片、未知内容”的优先级选择唯一主表示；
- 收藏和置顶内容不因普通历史上限或 Payload 容量治理被自动删除；
- 文本搜索继续使用包含匹配，不改为前缀匹配；
- 复制成功后才更新使用次数，自动粘贴只有在剪贴板写入成功后才激活目标应用；
- 统一 Store 的 staging、完整性校验、回滚和内存数据库降级语义保持不变；
- 同步协议、数据库业务字段和现有文件格式保持兼容。

窗口布局记录缓存属于 P3，纳入风险台账，但不进入 P1/P2 实施范围。

## P1 设计

### 图片预览请求与缓存

`ClipboardRowView` 使用两个明确的数据层次：

1. `ClipboardImagePreviewRequest`
   - 只包含 `path` 和规范化后的 `contentHash`；
   - 遵循 `Equatable`、`Hashable` 和 `Sendable`；
   - 可在 SwiftUI `body`、`.task(id:)` 和结果回写校验中同步创建；
   - 不访问文件系统。
2. `ClipboardImagePreviewSource`
   - 由后台 resolver 读取文件大小和修改时间后创建；
   - 缓存键继续由路径、大小、修改时间和内容哈希组成；
   - 只在 utility 优先级的 detached task 中使用。

图片加载流程为：

```text
SwiftUI 生成纯值 Request
    → utility task 读取文件属性
    → 生成 Source 和缓存键
    → 查询 NSCache 或使用 ImageIO 解码缩略图
    → MainActor 校验 Request 仍匹配
    → 发布预览
```

任务取消和来源变化只阻止过期结果发布，不承诺中断已经进入系统调用的文件 I/O。缩略图缓存继续保持 120 项和 128 MiB 上限。

### 剪贴板面板工作器

`Sources/MacTools/Features/Clipboard` 保留 MainActor 状态模型；后台执行能力放在
`Sources/MacTools/Application/AppEnvironmentWorkers.swift` 的 `ClipboardPanelWorker` actor。

工作器提供以下原子操作：

- 分页读取；
- 标记使用并返回最新页；
- 修改收藏状态并返回最新页；
- 删除单项并返回最新页；
- 清除非收藏项并返回最新页；
- 读取并规范化待复制图片。

每个“写入并返回快照”操作在 actor 中连续执行，中间不跨 `await`，防止写入完成后被旧查询覆盖。MainActor 模型为读取请求分配 generation，只有当前 generation 可以更新列表。已经进入数据库事务的收藏、删除和清空不因后续 UI 请求而取消。

### 复制和自动粘贴顺序

图片复制拆分为后台准备和主线程系统写入：

```text
后台读取并规范化图片
    → MainActor 写入 NSPasteboard
    → 后台标记使用并刷新列表
    → 发布一次本地变更
    → 可选：权限检查
    → 隐藏面板并激活原目标应用
    → 发送一次 Command+V
```

文本和文件 URL 不做图片准备，但数据库更新仍由工作器执行。

失败处理：

- 图片读取、规范化或剪贴板写入失败：不标记使用、不关闭面板、不激活目标、不发送粘贴；
- 数据库标记使用失败：剪贴板内容已经写入时记录错误并重新刷新，禁止伪造持久化成功；
- 自动粘贴权限不足：保留已经成功复制和标记使用的结果，显示现有权限提示，不发送粘贴；
- 新的粘贴激活请求继续取消旧 `PasteActivationAttempt`，保证最多发送一次粘贴。

## P1 验证门禁

P1 完成后必须同时满足：

1. 失败优先测试覆盖主线程文件属性调用、过期图片请求、旧查询覆盖、复制失败副作用和自动粘贴顺序；
2. P1 聚焦测试通过；
3. 完整 XCTest 使用仓库已确认的 AppKit 隔离方式通过：
   - 450 个非真实窗口点击测试同进程通过；
   - 1 个真实窗口点击测试单独通过；
4. `swift build -Xswiftc -strict-concurrency=complete` 无新增并发告警；
5. `scripts/rebuild_and_run_app.sh` 成功；
6. 打包应用完成文本、图片、文件的复制和自动粘贴验证；
7. 收藏、删除、清空操作保持响应，收藏内容及关联 Payload 保留；
8. Time Profiler 或等价采样确认主线程不再出现图片 `attributesOfItem`、SQLite 查询、图片文件读取和 Payload GC。

P1 门禁全部通过前，不开始 P2。

## P2 设计

### 轮询背压和载荷限额

轮询调度采用合并门：

- 同时最多一个执行中任务；
- 执行期间的新触发只设置一个 `needsAnotherPoll`；
- 当前任务结束后最多补跑一次；
- 补跑开始前重新读取最新 change count 和设置；
- 停止录制或应用终止时取消未来调度，不回滚已提交的持久化。

Pasteboard 读取按主表示优先级短路：

1. 存在文件 URL 时不读取图片；
2. 不存在文件 URL且存在非空文本时不读取图片；
3. 只有纯图片载荷才读取图片数据和执行 PNG 规范化。

图片限额：

| 限额 | 当前值 | 处理 |
| --- | ---: | --- |
| 单张压缩数据 | 64 MiB | 超限不解码、不持久化，消费 change count 并记录不含内容的诊断 |
| 单张像素数量 | 100 MP | 使用 ImageIO 元数据预检；超限不创建位图 |
| Payload 总量 | `maxCacheMegabytes`，默认 1024 MiB | 按 retention 顺序淘汰普通项；收藏和置顶项不自动删除 |

受保护 Payload 已占满容量时，新普通图片不进入历史；文本、URL、文件和文件夹记录不受图片容量阻断。

### 查询、索引和分页

查询输入统一为：

- 分类：全部、文本、图像、收藏；
- 去除首尾空白后的搜索词；
- 每页 100 条；
- 稳定游标：`isPinned`、`lastCapturedAt`、`createdAt`、`id`。

排序固定为：

```text
isPinned DESC
lastCapturedAt DESC
createdAt DESC
id ASC
```

数据库增加与空查询排序匹配的复合索引，并为收藏、类型筛选提供以筛选字段开头的排序索引。搜索继续使用转义后的包含匹配；长度较短或无法使用全文索引的查询允许扫描，但必须在后台执行、使用分页输出，并由 150 ms 防抖和 generation 抑制过期结果。

UI 初次只加载一页；接近列表末尾时请求下一页。分类或搜索词变化会取消旧的读取意图、清空游标并加载新首屏。分页拼接必须无重复、无遗漏，选中项失效时沿用现有回退规则。

### 轻量启动和后台迁移

`AppDelegate` 不再在属性初始化阶段创建完整 `AppEnvironment`。启动分为两层：

1. 轻量启动层
   - 立即设置 accessory 激活策略；
   - 安装只包含“正在准备数据”和“退出”的状态菜单；
   - 不安装剪贴板轮询、快捷键、超级右键和同步服务。
2. 完整运行时层
   - `AppBootstrapWorker` 在 utility 执行器完成设置读取、统一 Store bootstrap 和依赖种子创建；
   - MainActor 使用不可变种子创建 `AppEnvironment`；
   - 原子替换状态菜单，安装完整菜单、快捷键和运行时服务；
   - UI 验证启动参数在完整运行时就绪后执行。

迁移和不完整 Store 恢复按 200 条一批读取，不再一次 materialize 全表。图片逐项读取、写入和释放；staging 校验、cutover 标记及 rollback 安装顺序不变。

迁移期间不启动剪贴板录制，避免向即将切换的 Store 写入。bootstrap 失败继续创建隔离内存数据库并安装完整运行时，同时在状态菜单和日志中显示降级状态。连内存数据库也无法创建时，状态菜单提供错误信息和退出入口，不执行 `try!` 崩溃。

该边界替代 `2026-07-22-p2-startup-architecture-concurrency-design.md` 中“首次迁移继续同步完成”的旧结论。原因是新的性能目标要求 AppKit 主循环和最小状态界面先于大规模迁移可用；影响是迁移完成前功能暂不可用，但应用不会表现为无响应。

### 日志限额

`Logger.Configuration` 可注入并提供以下默认值：

| 范围 | 默认值 |
| --- | ---: |
| 内存消息 | 最近 2,000 条 |
| 当前日志文件 | 5 MiB |
| 备份数量 | 2 |
| 磁盘总上限 | 约 15 MiB |

内存消息使用有界环形缓冲。文件写入仍使用现有 utility 串行队列；写入前检查轮转条件，按 `debug.log.1`、`debug.log.2` 顺序移动，删除超出备份数量的最旧文件。当前文件和备份继续使用 `0600`，目录继续使用 `0700`。`flush()` 必须等待轮转和写入全部完成。

日志轮转不记录剪贴板内容、绝对用户路径、凭据或图片数据。

## P2 验证门禁

自动化验证包含：

- 慢轮询收到 100 次触发时，最大执行次数为 2，执行中数量始终为 1；
- 混合文本/图片载荷不会读取图片；
- 64 MiB、100 MP 和总 Payload 容量边界的前后值；
- 受保护内容不被容量治理删除；
- 10,000 条 fixture 的首屏只解码 100 条，游标分页无重复和遗漏；
- `EXPLAIN QUERY PLAN` 证明空查询使用新排序索引；
- 旧搜索语义、分类、选择和滚动加载保持一致；
- 5,000 条含图片的旧库迁移分批执行，导入、跳过和回滚结果不变；
- 阻塞型 bootstrap 下轻量状态菜单仍先安装；
- 日志并发写入、环形保留、两次以上轮转、权限和 flush 顺序。

完整验证重复 P1 门禁中的完整 XCTest、严格并发构建和打包应用检查，并补充：

- 启动至轻量状态菜单目标小于 250 ms，主线程无超过 100 ms 的 Store 工作；
- 迁移过程中状态菜单可交互，完成后快捷键、剪贴板、超级右键和同步正常安装；
- 轮询压力测试中 pending 数不超过 1；
- 日志文件总量和内存消息数量不超过设计值；
- 明暗背景、窗口尺寸、焦点、外部点击关闭和键盘导航无 UI 回归。
