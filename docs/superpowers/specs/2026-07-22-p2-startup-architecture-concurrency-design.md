# P2 启动、同步周期与并发安全优化设计

## 实施状态

- 状态：已实施并通过自动化验证。
- 验收结果：完整单元测试、严格并发零告警、打包启动和设置页检查已通过；真实双 Mac iCloud Drive 同步由人工验证。

## 目标与边界

P2 在不改变产品行为、同步协议和持久化格式的前提下，降低主线程启动负担，缩小同步协调器职责，并让严格并发检查反映真实的线程边界。

以下行为保持不变：

- 应用启动后立即安装菜单栏、快捷键、剪贴板轮询、超级右键和同步调度。
- 首次统一存储迁移仍在依赖装配前完成，失败时继续回退到隔离的内存数据库。
- 同步协议、保留策略、回执、容量判断、30 秒周期调度和错误状态映射不变。
- 截图、录屏、Finder 与超级右键的权限和用户交互不变。

## 方案

### 启动路径

数据库打开、迁移、设置读取和运行时依赖创建属于界面可用前的必要工作，继续同步完成。载荷暂存文件清理、载荷引用对账和孤立本地淘汰标记清理由独立维护工作器串行执行，并在 `AppEnvironment.start()` 完成运行时服务启动后异步调度。

维护工作器保持原有执行顺序和逐项容错：单项失败只记录错误，不阻止后续清理，也不影响应用启动。工作器只持有已经具备线程安全边界的仓储、载荷存储和日志对象。

### 同步周期

将文件协调、周期调度和状态发布保留在 `ICloudDriveSyncCoordinator`；将单次同步的协议读取、合并、保留决策、写入、回执和垃圾回收迁移到 `MacToolsCore` 的 `DriveSyncCycleRunner`。

周期运行器显式接收当前时间、设备名称和下载请求能力，消除对 `Date()`、`Host.current()` 与 `FileManager.default` 的隐式依赖。这样可以直接使用临时数据库和临时目录验证单次周期，同时让协调器只负责串行化和生命周期。

### 并发安全

按所有权而不是消除告警数量处理严格并发检查：

- 纯值模型补齐可推导的 `Sendable`；不包含可变共享状态。
- AppKit/SwiftUI 界面控制器和事件监听生命周期明确隔离到主 Actor。
- 后台工作只传递值类型或现有线程安全仓储；对不具备并发安全的服务不使用无依据的 `@unchecked Sendable`。
- 截图录制和超级右键跨线程对象只在其既有串行队列或主 Actor 边界内访问；若需要声明 unchecked，必须由现有锁、串行队列或框架回调约束支撑。

## 验证

- 聚焦测试锁定维护执行顺序、同步周期的空仓写入与稳定重跑，以及同步导出次数、回执和目录扫描约束。
- 严格并发构建记录唯一告警位置变化，确保本次不引入新的跨 Actor 风险。
- 运行完整 `swift test`。
- 使用打包应用验证启动、菜单栏、设置面板和运行状态；涉及权限的实际双机同步由人工验证覆盖。

## 风险控制

- 不将首次迁移异步化，避免界面先绑定临时状态后再切换存储。
- 不改变同步文件格式和写入顺序；运行器抽取以机械迁移为主，并用原有源代码约束与新增集成测试双重锁定。
- 并发标注分批提交，每批都执行聚焦测试和严格并发构建，避免一次性扩大诊断范围。
