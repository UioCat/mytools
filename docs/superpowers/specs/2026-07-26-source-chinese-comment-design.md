# MacTools 生产源码中文注释设计

## 文档状态

- 状态：设计已确认，待实施。
- 适用范围：`Sources/` 下 105 个生产 Swift 文件。
- 排除范围：`Tests/`、`.build/`、`build/`、外部依赖、资源文件和生成物。
- 行为边界：只补充或整理注释，不修改运行时行为、公开接口、线程模型和数据格式。

## 目标

建立统一、可持续维护的中文注释基线，使读者可以依次理解：

1. 文件在模块中的职责和边界；
2. 类型承担的状态或行为；
3. 每个方法的目的、输入输出和关键副作用；
4. 核心流程中的不变量、并发控制、事务边界和异常降级原因。

注释用于解释意图、约束和原因，不逐行复述 Swift 语法。

## 注释层级

| 层级 | 覆盖范围 | 格式 | 内容 |
| --- | --- | --- | --- |
| 文件 | 每个生产 Swift 文件 | 文件顶部 `//` | 模块职责、主要协作者和系统边界 |
| 类型 | `class`、`struct`、`enum`、`actor`、`protocol` 和重要扩展 | 声明前 `///` | 类型用途、状态所有权和线程约束 |
| 方法 | `func`、`init`、`deinit`、`subscript`、重写方法和协议实现 | 声明前 `///` | 方法目的、关键参数、返回值、副作用、错误或调用约束 |
| 核心代码 | 关键分支和状态转换 | 代码块前 `//` | 为什么采用当前顺序、锁或事务保护什么、如何抑制过期结果 |
| 分区 | 同一类型内职责不同的代码组 | `// MARK: -` | 按生命周期、输入输出、同步、持久化或展示职责分组 |

## 文件级注释

每个文件在 `import` 前增加简洁的中文说明，通常为两至四行：

```swift
// 剪贴板数据库访问层。
// 负责在 GRDB 事务内持久化条目、字段时钟和同步状态，
// 不承担剪贴板读取或界面状态管理。
```

文件说明必须回答“负责什么”和“不负责什么”。单一模型文件可以缩短为一至两行，但不能只把
文件名翻译成中文。

## 类型与方法注释

### 覆盖规则

以下声明均需要中文文档注释：

- 所有具名类型和协议；
- 所有显式 `init`、`deinit` 和 `subscript`；
- 所有实例方法、静态方法和类方法；
- AppKit、SwiftUI、ScreenCaptureKit、Carbon、Accessibility 等框架的重写方法和回调；
- 协议要求的实现，即使方法含义由协议名称基本确定；
- 私有辅助方法和嵌套类型中的方法。

闭包字面量、属性观察器和简单计算属性不按独立方法处理；当其承担状态转换、资源释放或线程
切换时，在属性或代码块前增加说明。

### 内容规则

短方法使用一句话说明意图：

```swift
/// 返回当前设置是否允许同步剪贴板图片。
func shouldSyncImages() -> Bool
```

存在约束或副作用时补充必要字段：

```swift
/// 合并远端快照并在同一数据库事务内更新本地字段时钟。
///
/// - Parameters:
///   - snapshot: 已通过协议版本和摘要校验的远端快照。
///   - deviceID: 产生本次合并结果的本机设备标识。
/// - Returns: 需要在下一轮同步中回写的本地变更集合。
/// - Throws: 数据库写入或载荷校验失败时抛出对应错误。
func merge(_ snapshot: SyncSnapshot, deviceID: String) throws -> SyncChanges
```

方法注释优先说明：

- 业务目的和调用时机；
- 是否读写磁盘、数据库、剪贴板或系统权限；
- 是否必须在 Main Actor、串行队列或锁内调用；
- 是否会启动、取消或替换异步任务；
- 返回值为 `nil`、空集合或降级结果时的语义；
- 错误是向上抛出、记录后忽略，还是转换为用户状态。

参数和返回值含义清晰且没有额外约束时，不机械添加 `Parameters` 或 `Returns` 段落。

## 核心代码注释

以下区域需要在方法文档之外增加中文行内说明：

| 领域 | 需要说明的内容 |
| --- | --- |
| 同步 | generation、逻辑时钟、冲突胜负、tombstone、远端对象导入和过期结果保护 |
| 存储 | GRDB 事务、staging/rename、回滚目录、文件权限、内容寻址和垃圾回收顺序 |
| 凭据 | 公开派生材料的安全边界、AES-GCM AAD、迁移来源、删除标记和副本对账 |
| 并发 | Actor/Main Actor 边界、锁保护字段、取消点、任务所有权和回调发布线程 |
| 权限 | TCC 预检、系统设置跳转、授权恢复和能力降级 |
| 系统集成 | event tap、Finder Automation、Carbon 热键、Accessibility 和 ScreenCaptureKit 生命周期 |
| UI 状态 | 草稿与已保存设置、焦点、面板展示身份和异步结果回写条件 |

行内注释放在需要解释的代码块之前，说明“为什么”和“不变量”。不得为赋值、普通条件判断或
显而易见的框架调用逐行添加说明。

## 文案与维护规则

- 注释正文使用简体中文，类型名、方法名、配置 key 和框架术语保留真实标识。
- 一句话表达一个结论，避免“这里处理”“执行相关逻辑”等空泛描述。
- 不记录提交过程、临时方案、作者对话或无法从代码确认的推测。
- 不把潜在缺陷写成已经满足的不变量；未修复风险只说明当前行为，不通过注释掩盖问题。
- 已有准确注释保留并统一为中文；过期、重复或与实现冲突的注释直接替换。
- 注释随相邻代码缩进，不改变格式化风格，不大范围重排声明。

## 验证标准

### 静态覆盖

- 105 个生产 Swift 文件均具有文件级中文说明；
- 所有目标方法声明前均存在中文文档注释；
- 所有具名生产类型均存在中文文档注释；
- 核心模块至少逐文件人工复核，不只依赖正则计数；
- `git diff --check` 无空白错误，改动范围只包含注释和必要空行。

### 构建与测试

- `swift test` 全部通过；
- `swift build -Xswiftc -strict-concurrency=complete -Xswiftc -warn-concurrency` 通过；
- 注释不引入新的编译警告；
- 对 `Sources/` 执行敏感字段扫描，确认注释没有加入真实凭据、用户路径或运行时数据。

### 人工抽查

从同步、存储、凭据、权限、ScreenCaptureKit、Finder、超级右键和 SwiftUI 各选择至少一个文件，
核对注释是否准确解释真实实现，并确认没有把已知风险描述成已解决行为。

## 风险与控制

| 风险 | 控制方式 |
| --- | --- |
| 批量注释重复代码表面含义 | 以职责、约束和副作用为主要内容；抽查后删除无信息量注释 |
| 注释与实现不一致 | 写注释前读取完整类型和调用方；核心模块按调用链复核 |
| 大范围修改夹带行为变化 | 分阶段检查 diff，只允许注释与必要空行 |
| 文档注释触发格式或编译问题 | 每阶段运行窄范围构建，最终运行完整测试与并发检查 |
| 后续代码修改导致注释过期 | 注释稳定业务意图和不变量，避免记录易变化的实现细节 |
