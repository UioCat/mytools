# Excel 剪贴板文本优先设计

## 目标

当 Excel 等应用复制的内容同时包含文本和图片表示时，MacTools 将其记录为文本，避免从剪贴板历史再次粘贴后变成图片。仅包含图片的剪贴板内容仍按图片处理。

## 根因

`SystemPasteboardClient` 会同时读取剪贴板中的文本、文件 URL 和图片数据。`ClipboardClassifier` 当前按“文件 URL、图片、文本”的顺序选择唯一内容类型，因此 Excel 单元格区域附带的图片表示会覆盖同一载荷中的制表符分隔文本。`ClipboardService` 随后只持久化被选中的图片数据，重新粘贴时只能写回 PNG。

`ClipboardContentHasher` 使用相同的“文件 URL、图片、文本”优先级计算内容哈希。调整分类优先级时必须同步调整哈希优先级，确保去重标识与实际持久化内容一致。

## 方案比较

| 方案 | 优点 | 代价与边界 |
| --- | --- | --- |
| 混合载荷全局文本优先（采用） | 改动小；不依赖应用名称；Excel、Numbers、网页表格和富文本复制均可恢复为可编辑文本 | 同时提供文本回退和图片的少数应用会被记录为文本 |
| 仅对 Excel 应用文本优先 | 对其他来源影响更窄 | 当前只记录本地化应用名称，缺少稳定的 bundle identifier；还会遗漏 Numbers、WPS 等同类场景 |
| 保存并回放全部剪贴板表示 | 可由目标应用自行选择文本、富文本或图片 | 需要扩展数据模型、数据库、同步格式、缓存和粘贴协议，超出本次问题范围 |

## 当前方案

剪贴板载荷继续只选择一种主表示，优先级调整为：

1. 文件 URL；
2. 非空文本；
3. 图片数据；
4. 未知内容。

文件 URL 仍保持最高优先级，避免 Finder 复制文件时被路径文本替代。混合文本和图片载荷选择文本后，保留原有的文本与 URL 字符串分类规则；Excel 单元格区域中的 Tab 和换行不做改写，重新粘贴到表格时由目标应用恢复行列结构。

内容哈希采用相同优先级。`ClipboardService` 的持久化和 `PasteActionService` 的回放逻辑无需调整：文本项不会写入图片缓存，回放时继续通过系统纯文本类型写入剪贴板。

## 边界

- 纯图片、截图和没有文本表示的图表仍记录为图片。
- 当前方案保留单元格显示值和 Tab/换行结构，不保留字体、颜色、公式、合并单元格或 Office 专用格式。
- 已经按图片存入历史的项目不包含原始文本，无法自动恢复；修复后重新复制的内容才会按新策略记录。
- 不新增来源应用白名单、设置开关、数据库迁移或同步格式。

## 测试与验证

- 新增混合文本和图片载荷的分类测试，先证明当前实现错误地选择图片，再验证修复后选择文本。
- 断言混合载荷与同文本的纯文本载荷生成相同内容哈希，防止分类和去重语义分离。
- 保持纯图片、文件 URL、普通文本和 URL 文本现有测试通过。
- 先运行聚焦测试 `swift test --filter ClipboardClassifierTests`，再运行完整 `swift test`。
- 运行 `git diff --check` 和仓库敏感信息扫描。
