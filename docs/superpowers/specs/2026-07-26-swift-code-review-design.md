# Swift 代码审查规范设计

## 背景

MacTools 已有针对实现、测试、权限、打包和提交的仓库约定，但缺少统一的 Swift 代码审查标准，也没有明确规定何时必须引入独立子 Agent 审查。为了让每次任务默认经过独立检查，同时避免纯粹的极小低风险改动产生不必要开销，需要在仓库根目录建立可执行的审查规范和审查记录。

## 目标

- 根目录新增 `SWIFT_CR.md`，作为 Swift 与相关工程改动的统一代码审查规范。
- 根目录新增 `REVIEW.md`，记录最近一次强制审查的范围、发现、修复和验证证据。
- 在 `AGENTS.md` 中建立“默认审查、严格豁免”的自动触发规则。
- 强制审查由一个独立子 Agent 执行；该 Agent 不仅报告问题，还负责修复确认的问题并复审。
- 主 Agent 保留最终范围检查、验证、提交和推送责任。

## 非目标

- 不增加 Git hook、CI 工作流或依赖外部审查服务。
- 不要求极小改动更新 `REVIEW.md`，避免审查记录自身导致递归触发。
- 不让审查子 Agent 创建提交或推送分支。
- 不以编译或测试通过代替代码审查。

## 文件职责

### `SWIFT_CR.md`

该文件定义：

- 审查目标、输入范围和审查顺序；
- Swift、SwiftUI、AppKit、并发、持久化、安全、权限、性能和测试的检查项；
- P0 至 P3 的问题等级和处理规则；
- 审查子 Agent 的修复边界；
- `REVIEW.md` 的填写要求；
- 复审、验证和退出条件。

### `REVIEW.md`

该文件保存最近一次强制审查的结果，包括：

- 任务与基线；
- 触发原因和改动统计；
- 审查结论；
- 带文件及行号的发现；
- 已实施修复；
- 验证命令与结果；
- 未解决问题和剩余风险。

每次强制审查覆盖其中的“最近一次审查”内容，不维护无限增长的历史日志；历史由 Git 保存。

### `AGENTS.md`

该文件只保留代理执行所需的触发规则和流程摘要，并链接到根目录的 `SWIFT_CR.md` 与 `REVIEW.md`，避免在多个文件重复完整检查表。

## 触发规则

主 Agent 必须在首次任务改动前记录 Git 基线提交。任务完成实现和初步验证后，以该基线到当前工作树的完整差异为审查范围；新增但未跟踪的任务文件也必须纳入文件数和行数统计。生成产物、忽略文件和任务开始前已有的用户改动不属于本次统计。

任何改动默认必须启动审查子 Agent。只有同时满足以下全部条件，主 Agent 才能将任务认定为“极小改动”并豁免：

1. 本次任务最多改动 2 个文件。
2. 新增行与删除行合计不超过 30 行。
3. 不新增、删除或重命名文件。
4. 不改变跨模块接口、持久化格式、依赖或构建配置。
5. 不涉及数据库迁移、凭据与安全、并发模型、系统权限、Finder 集成、截图录屏、自动粘贴或打包签名。
6. 改动是局部、低风险且已完成对应的聚焦验证。

任一条件不满足即强制审查。主 Agent 不得以“看起来简单”、测试已通过或仅修改文档为由扩大豁免范围。使用豁免时，最终交付说明必须列出文件数、变更行数、验证结果和逐项满足条件的理由。

`REVIEW.md` 中由审查流程产生的记录改动不参与当前任务的触发统计。

## 自动审查与修复流程

1. 主 Agent 记录任务基线，完成任务范围内的实现和初步验证。
2. 主 Agent统计基线到当前工作树的任务改动，并判断是否满足全部豁免条件。
3. 强制审查时，主 Agent 启动一个独立子 Agent，并提供：
   - 任务目标和已确认的产品约束；
   - Git 基线及完整差异范围；
   - `AGENTS.md` 和 `SWIFT_CR.md`；
   - 已执行的验证及结果；
   - 任务开始前已有、不得修改的用户改动。
4. 审查子 Agent 先完成独立检查，再修改代码。它必须：
   - 以可复现的行为问题为中心报告发现；
   - 为每项发现标记 P0 至 P3、文件和行号；
   - 修复所有确认的 P0、P1、P2，以及无争议且在任务范围内的 P3；
   - 不进行无关重构，不修改任务外用户内容；
   - 运行与修复直接相关的聚焦验证；
   - 将结论、修复和验证写入 `REVIEW.md`。
5. 审查子 Agent 对修复后的完整差异再次检查。仍有确认问题时，由同一子 Agent 继续修复与复审，直到没有未解决的 P0 至 P2，或出现无法在授权范围内解决的明确阻塞。
6. 主 Agent 检查子 Agent 的所有修改，运行仓库要求的最终验证，并确认 `REVIEW.md` 与实际结果一致。
7. 主 Agent 负责范围核对、密钥扫描、提交和推送。审查子 Agent 不执行 Git 提交或推送。

如果子 Agent 不可用、启动失败或上下文不足，强制审查不能被静默跳过。主 Agent必须说明阻塞并停止在提交或完成声明之前。

## 审查内容

审查顺序以用户影响和风险为先：

1. 正确性与回归：状态转换、错误路径、边界条件、兼容性和产品约定。
2. 并发与生命周期：Actor 隔离、主线程阻塞、取消、过期结果、任务及观察者释放。
3. 数据与安全：迁移、回滚、原子性、敏感信息、文件权限和日志暴露。
4. macOS 集成：AppKit/SwiftUI 边界、TCC 权限、Finder、ScreenCaptureKit、辅助功能和签名身份。
5. 性能与资源：主 Actor 工作量、重复 I/O、数据库访问、缓存、内存和文件句柄。
6. 测试与验证：行为变更是否有确定性测试，人工验证是否覆盖适用场景。
7. 可维护性：职责边界、命名、重复逻辑和注释是否准确；纯风格偏好不得作为阻断问题。

## 问题等级

- **P0**：会导致数据泄露、不可恢复的数据损坏、严重安全问题或应用无法发布。
- **P1**：常见路径中的崩溃、错误结果、权限回归、死锁或核心功能不可用。
- **P2**：特定条件下的真实功能缺陷、资源泄漏、兼容性问题或明显缺失的必要测试。
- **P3**：不会立即破坏功能，但有明确维护成本或低风险改进价值的问题。

只有没有未解决的 P0、P1、P2 时，审查才能记为通过。无法确认或仅属偏好的意见应记录为非阻断建议，不得伪装成缺陷。

## 验证策略

这次只变更流程文档，不改变可执行产品行为，因此实施阶段至少执行：

- 检查三个根目录文件之间的链接、术语、阈值和职责是否一致；
- `git diff --check`；
- 仓库敏感字段扫描，并人工确认匹配项不包含真实凭据；
- 按新规则启动独立子 Agent，完成本次文档改动的首次审查、修复和 `REVIEW.md` 记录；
- 主 Agent 检查审查修复并再次运行文档验证。

## 验收标准

- `SWIFT_CR.md` 能让未参与实现的子 Agent 独立完成审查与修复。
- `REVIEW.md` 能清楚证明审查范围、发现、修复和验证结果。
- `AGENTS.md` 明确任何改动默认触发审查，并完整列出极小改动的六项豁免条件。
- 触发统计包含新文件，不会因更新 `REVIEW.md` 产生递归审查。
- 强制审查失败时不能提交或宣称完成。
- 文档不包含真实用户路径、凭据或运行时敏感数据。
