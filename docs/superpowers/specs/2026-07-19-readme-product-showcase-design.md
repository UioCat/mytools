# README 产品展示优化设计

## 目标

将 `README.md` 从偏开发者的功能与实现清单，调整为面向普通用户的产品介绍页。读者应能在首页快速理解 MacTools 的用途、核心功能、默认快捷键、系统要求和必要权限，并通过真实界面截图建立直观预期。

## 读者与内容原则

- 主要读者是希望了解或使用 MacTools 的普通 macOS 用户。
- 先介绍用户能够完成的事情，再说明使用条件和开发方式。
- 保留准确、可操作的信息，移除轮询周期、缓存实现、内部路由、诊断链路等首页不需要的细节。
- 详细架构、人工验证和超级右键诊断继续由现有 `docs/` 文档承载，README 只提供入口。
- 不增加尚未实现的功能描述，不把计划能力写成当前能力。

## README 信息结构

README 按以下顺序组织：

1. 产品名称、一句话定位和核心能力概览。
2. 真实界面预览，优先让用户看到产品实际效果。
3. 核心功能介绍：剪贴板、翻译、超级右键、截图与录屏、窗口布局和设置。
4. 默认快捷键速查表。
5. 系统要求、必要权限与本地构建运行方式。
6. 数据与隐私提示。
7. 面向贡献者的精简开发入口及详细文档链接。

## 截图方案

计划拍摄四至五张打包应用的真实界面，最终数量以清晰展示功能且避免重复为准：

1. 剪贴板历史：展示分类、搜索、收藏和内容列表。
2. 翻译：展示输入、译文、复制和系统语音朗读入口。
3. 超级右键：展示文本或 Finder 场景中的快捷动作面板。
4. 截图与录屏：优先展示截图标注编辑器；若录屏模式切换能在同一画面清楚呈现，则一并保留。
5. 设置与窗口布局：版面允许时展示快捷键、权限或布局配置。

图片统一放在 `docs/images/` 下，采用稳定、语义清楚的英文文件名，并在 README 中使用仓库相对路径引用。截图保持一致的显示比例和简洁背景，避免过大的原始图片拖慢页面加载。

## 真实性与隐私处理

- 截图必须来自 `build/MacTools.app` 的实际运行界面，不使用设计稿或生成式图片替代产品界面。
- 拍摄前准备专用演示内容，避免真实剪贴板历史、文件名、翻译内容、录屏内容和账户信息进入截图。
- 百炼 API Key 不得出现在任何截图中；需要展示翻译功能时，只截取主翻译界面，不展示凭据输入区域。
- 对系统菜单、Finder、路径或其他无法避免的个人信息，使用完全不透明的色块覆盖；不得只使用仍可能辨认或恢复内容的轻度模糊。
- 提交前逐张以原始分辨率检查账户名、目录名、窗口标题、菜单栏状态、通知、剪贴板内容和其他可识别信息。

## 实现与验证

1. 按 `scripts/rebuild_and_run_app.sh` 构建、签名并启动打包应用。
2. 使用无个人信息的演示数据依次打开目标功能并拍摄真实界面。
3. 对截图进行裁切、必要的不可逆遮挡和体积优化，不改变功能界面本身。
4. 重写 README 并检查图片在 GitHub Markdown 中的相对路径和显示尺寸。
5. 运行 `git diff --check`，检查所有文档链接和命令。
6. 以原始分辨率复核每张图片的隐私信息，并执行仓库敏感信息扫描。

本次只调整文档与配图，不改变应用行为，因此不要求新增单元测试。打包运行和实际界面检查用于证明截图来自当前产品；如果环境权限限制导致某项功能无法拍摄，应在交付说明中明确剩余边界，不用模拟图冒充真实界面。
