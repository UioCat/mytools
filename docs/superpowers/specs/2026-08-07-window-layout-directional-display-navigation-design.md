# 窗口布局方向跨屏与满屏可靠性设计

## 目标

窗口布局需要同时满足以下行为：

- “满屏”继续表示普通窗口铺满当前显示器可用区域，不进入 macOS 原生全屏 Space；
- 单次满屏快捷键应可靠收敛到目标位置和尺寸；
- 窗口已位于某个屏幕边缘时，重复执行同方向布局可进入该方向的相邻显示器；
- 跨屏后窗口落在目标显示器的内侧边缘，例如左半屏继续向左时进入左侧显示器的右半屏；
- 支持显示器左右、上下及错位排列，不把数组顺序当成物理方向；
- 用户手动移动或缩放窗口后，下一次快捷键按普通首次布局处理，不误判为重复动作。

## 现状与根因

### 满屏偶发不到位

`SystemWindowLayoutService` 将位置和尺寸分别写入 Accessibility 属性，最多执行 3 轮写入，并在 `120 ms` 后终止验证。现有运行日志已出现满屏请求中所有 AX 写入均返回成功，但位置和尺寸在时限内都未达到目标的记录。

AX 写入返回成功只说明请求已被目标应用接受，不代表应用动画、内部约束或窗口服务器已经完成最终布局。固定 `120 ms` 时限会把仍在调整中的窗口提前判定为失败。当前服务也没有处理目标应用的 `AXEnhancedUserInterface` 状态；Rectangle 在写入窗口 frame 前会暂时关闭该状态，并在结束后恢复，以降低部分应用对辅助功能窗口调整的干扰。

### 方向快捷键无法跨屏

当前服务根据窗口矩形与 `NSScreen.frame` 的交集选择所在屏幕，随后始终使用该屏幕的 `visibleFrame` 计算目标。代码中没有以下能力：

- 识别同一布局动作是否被连续执行；
- 记录并核对上次成功应用的目标矩形；
- 查找指定物理方向的相邻显示器；
- 跨屏时将布局翻转到目标显示器的内侧边缘。

因此重复执行左、右布局只会重新应用当前屏幕的同一目标，上下方向也没有对应布局模式。

## 方案比较

| 方案 | 优点 | 风险与成本 | 结论 |
| --- | --- | --- | --- |
| 延长重试并按屏幕数组切换 | 改动最少 | 无法可靠处理上下或错位排列；无法避免手动移动后的误跨屏 | 不采用 |
| Rectangle 式重复动作判断 + 物理方向导航 + AX 收敛适配 | 行为可预测；支持任意常见显示器排列；纯几何逻辑可测试 | 需要扩展布局模型、状态记录和应用层适配 | 采用 |
| 直接依赖或调用 Rectangle | 可复用成熟程序行为 | 引入外部应用依赖，无法融入现有设置、快捷键和状态边界 | 不采用 |

## 当前方案

### 布局模式与默认快捷键

在现有八种模式上新增：

| 模式 | 默认快捷键 | 目标区域 |
| --- | --- | --- |
| 上半屏 | `Control+Command+Up` | 当前显示器可用区域的上半部分 |
| 下半屏 | `Control+Command+Down` | 当前显示器可用区域的下半部分 |

设置页将现有“半屏”分为“水平半屏”和“垂直半屏”，每组仍保持两个动作，避免设置窗口出现四列压缩。超级右键面板继续使用现有动态高度和滚动约束容纳新增按钮。

上下方向使用 AppKit 全局坐标：上方显示器的中心 `y` 大于当前显示器，下方显示器的中心 `y` 小于当前显示器。写入 AX 前继续通过统一坐标转换映射到 AX 顶部原点坐标系。

### 重复动作判定

按窗口 ID 保存最后一次已经回读确认成功的结果，包含：

- 最终布局模式；
- 最终目标 AX 矩形；
- 触发布局的按钮 ID。

只有同时满足以下条件才视为重复动作：

1. 本次解析出的布局模式与上次最终布局模式相同；
2. 当前实际位置和尺寸仍与上次目标矩形匹配，容差沿用 `1 pt`；
3. 当前按钮只包含一个内置布局模式；自定义循环按钮继续遵循原有模式循环，不触发隐式跨屏。

如果窗口被用户、系统或其他应用移动或缩放，实际矩形不再匹配，上次结果不参与跨屏判断。

### 方向导航与内侧落点

可跨屏的对应关系如下：

| 重复模式 | 查找方向 | 目标显示器布局 |
| --- | --- | --- |
| 左半屏 / 左 1/3 / 左 2/3 | 左 | 右半屏 / 右 1/3 / 右 2/3 |
| 右半屏 / 右 1/3 / 右 2/3 | 右 | 左半屏 / 左 1/3 / 左 2/3 |
| 上半屏 | 上 | 下半屏 |
| 下半屏 | 下 | 上半屏 |

候选显示器必须位于请求方向的半平面内。选择顺序为：

1. 优先选择与当前屏幕在垂直于移动方向的轴上存在投影重叠的显示器；
2. 再比较沿移动方向的边缘距离；
3. 距离相同时比较垂直轴中心偏移和稳定屏幕标识，保证结果确定。

没有该方向候选显示器时，继续应用当前显示器上的请求布局，不循环到反方向。跨屏目标使用目标显示器自己的 `visibleFrame` 重新计算，适配不同分辨率、缩放比例、菜单栏和 Dock 位置。

### 满屏与通用 frame 收敛

保留位置和尺寸独立回读、只重写未到位属性、最新请求取消旧请求的现有边界，并增加两层适配：

1. 开始写入前读取目标应用的 `AXEnhancedUserInterface`。原值为 `true` 时暂时设置为 `false`；请求成功、失败或取消时恢复原值。读取或设置失败只记录错误，不阻止普通 frame 写入。
2. 将固定间隔和 `120 ms` 总时限改为有界退避验证。单次请求最多写入 5 轮，验证窗口最长 `500 ms`；每轮基于最新回读结果生成写入计划。新快捷键请求到来时立即取消等待，旧请求不得继续写入或恢复新请求持有的状态。

跨显示器时首轮采用适合屏幕约束变化的“尺寸 → 位置 → 尺寸”计划；同屏操作保留当前按放大、缩小和混合变化选择顺序的策略。所有场景仍以最终回读矩形为成功依据，不能仅凭 AX 返回值记录成功。

### 旧设置迁移

新增模式不能覆盖用户已有的可见动作和快捷键选择：

| 旧配置状态 | 迁移行为 |
| --- | --- |
| 可见模式仍等于旧版八种默认值 | 自动追加上半屏、下半屏 |
| 可见模式已被用户修改 | 原样保留；新模式可在设置中手动启用 |
| 快捷键仍等于旧版默认集合 | 自动追加上下默认快捷键 |
| 快捷键已被用户修改 | 原样保留，不抢占用户组合键 |

迁移在 `WindowLayoutSettings` 解码或统一的规范化入口完成，保存后写回新结构。已有自定义按钮继续按原模式解码。

## 组件边界

| 组件 | 职责 |
| --- | --- |
| `WindowLayoutMode` / `WindowLayoutCalculator` | 定义上下模式、方向映射和目标区域计算 |
| `WindowScreenNavigationPolicy` | 使用纯 `CGRect` 数据判断物理相邻屏幕和跨屏后的目标模式 |
| `WindowFrameApplicationPolicy` | 定义同屏/跨屏写入计划、容差、退避间隔和总边界 |
| `SystemWindowLayoutService` | 读取聚焦窗口与屏幕、管理请求代次、AX 状态、回读和成功记录 |
| 设置与快捷键展示 | 展示新模式、迁移旧默认值并即时注册上下快捷键 |

`MacToolsCore` 不直接依赖 `NSScreen` 或 Accessibility。屏幕 frame 在应用适配层转换成纯领域输入，保证几何导航可由单元测试覆盖。

## 异常与边界

- 只有一个显示器或指定方向不存在显示器时，不跨屏、不报错；
- 目标应用不允许设置尺寸时，位置仍按可写能力处理，最终未满足完整目标则记录失败；
- 窗口最小尺寸超过目标区域时，不伪造成功状态；
- 无法取得窗口 ID 时仍执行当前布局，但不保存依赖窗口 ID 的重复动作状态；
- 快速交替按不同快捷键时，只有最新请求可以提交布局状态；
- AX 状态恢复采用请求持有关系，取消旧请求不能覆盖新请求已经设置的状态。

日志只记录请求代次、布局模式、方向、失败组件和 AX 错误码，不记录窗口标题、应用内容或用户数据。

## 测试与验证

### 自动测试

| 范围 | 场景 |
| --- | --- |
| 布局计算 | 上下半屏矩形、预览方向、不同 `visibleFrame` 原点 |
| 屏幕导航 | 左右、上下、错位、不同尺寸、多个候选、无候选 |
| 重复动作 | 首次不跨屏、目标匹配后跨屏、手动移动后不跨屏、跨屏后下一次先落到同屏请求侧 |
| 比例保持 | 1/3、2/3 跨屏后保持比例并翻转边缘 |
| frame 应用 | 跨屏首轮顺序、最多 5 次写入、`500 ms` 边界、取消旧代次 |
| 设置兼容 | 旧默认配置自动补充、用户自定义配置保持、上下快捷键注册 |

先运行窗口布局、设置和快捷键聚焦测试，再运行完整 `swift test`。

### 打包应用验证

使用 `scripts/rebuild_and_run_app.sh` 构建并启动打包应用，在 Chrome 和至少一个原生 AppKit 应用中验证：

1. 从左/右三分之一、半屏、居中状态分别触发满屏，各连续执行至少 20 次；
2. 两台显示器左右排列时验证左侧到右侧、右侧到左侧的内侧落点；
3. 显示器上下排列时验证上半屏、下半屏的双向跨屏；
4. 手动移动窗口后再次按同一快捷键，确认先应用当前屏幕布局；
5. 快速交替执行布局，确认旧请求不覆盖最新结果；
6. 检查设置页明暗外观、尺寸调整、键盘导航和新增布局预览。

若当前物理显示器排列无法覆盖上下场景，该场景保留为明确的人工验证边界，不以单元测试替代运行时 TCC 和多屏验证结论。

## 版本

该变更新增上下布局并改变方向快捷键的跨屏行为，属于用户可感知的较大行为扩展。稳定版本按次版本递增为 `0.3.0`；发布标签和 Release 流程不在实现提交中自动触发。

- Rectangle [`AccessibilityElement.swift`](https://github.com/rxhanson/Rectangle/blob/main/Rectangle/AccessibilityElement.swift)：分别写入 AX 尺寸和位置，并临时处理增强辅助功能状态。

当前方案只复用行为原则，保持 MacTools 的领域模型、设置格式、重试状态机和依赖边界。
