# 同步可靠性与自动化验证

## 历史问题与根因

同步使用 iCloud Drive 传输每台设备独立的快照和内容对象。文件的本地原子写入不代表另一台设备能同时看到所有文件；目录可暂时不完整，旧清单也可能迟到。

| 历史修复 / 复现场景 | 根因与影响 | 当前处理 |
| --- | --- | --- |
| `cd0a320` 修复清单冲突和随机重复快照；双端空闲仍不断增版 | 接收回执也触发新发布，另一端继续确认该发布。双设备测试中 12 轮空闲同步将双方 revision 从 6 推至 18 | 按合并后的实际快照内容决定发布，回执变化不单独生成 revision |
| 同一文本或图片同时复制 | 记录 ID 和字段时钟可合并，但来源、标题等展示元数据按到达顺序覆盖 | 合并最早创建时间及最新采集元数据，同时间使用确定性排序，避免反复覆盖 |
| 等价清单版本被报告冲突 | 多个等价版本都能支配其他版本，旧解析器要求唯一文件版本；同 revision 不同快照又可能被向量误判为赢家 | 等价发布选当前文件；同 revision 不同快照保留冲突，禁止猜测丢弃 |
| 内容迟到，或冲突设备让空闲周期反复全盘扫描 | 快照清单不变但对象尚未到达；丢弃全部观察又导致健康设备和历史目录重复读取 | 缓存已校验副本；缺失或损坏对象下一周期只刷新对象目录；仍逐轮检查 manifest，冲突解除后恢复导入 |
| 旧清单迟到、本地数据库恢复、发布中断 | 旧快照已回收时只有作废证据；或只追平本机 revision，没有导入较新的本机云端数据 | 使用完整匹配的本地台账恢复旧指针；较新本机快照必须完整导入，内容缺失或损坏时禁止替换原清单或确认进度；不确定发布保留 outbox |
| 离线设备恢复已删除内容 | 当前可见目录不等于完整成员名单；删除标记在可见设备确认后被提前清理 | 同代际保留并转发全部已知删除标记；并发删除确定性选取记录，避免来源互换后云端证据消失；显式重置后清理旧代际 |
| 重置或移除设备后无法继续发布 | 新代际无法替换旧代际清单；移除设备清除了向量分量，使因果历史回退 | 有 reset marker 才淘汰旧代际；移除成员保留历史向量分量 |
| 已清理快照仍被统计为占用容量 | 发布增加缓存统计，物理回收未同步扣减 | 清理返回实际回收字节；部分失败后重新盘点 |
| 设置已入库、后续发布失败 | receipt 跳过了下次导入，运行时可能一直收不到设置 | 成功重试重新交付已合并设置；相同设置跳过重复刷新 |
| 收到远端设置后后台同步停止 | 主线程设置回调使旧定时器失效，运行周期已结束时没有补跑 | 相同配置不改变周期令牌；配置改变后启动替代周期；主动同步使用独立令牌淘汰之前的定时器，既防止周期链累积，也不会取消重置或移除设备 |
| 同步空间达到旧上限后仍显示容量满，目录有数据但显示普通历史 `0 / 500` | 容量分母为应用内部配额，普通历史计数不包含收藏、设置、旧快照和等待回收对象；两者无法说明实际目录内容 | 新版固定只同步收藏与相关配置，取消同步配额和普通历史计数，只展示目录占用 `MB`；零收藏也可有协议元数据占用 |
| 取消收藏后旧快照重新带回收藏，或旧 `全部历史` 配置继续上传普通剪贴板 | 仅缩小导出范围不足以处理旧副本中的收藏时钟与普通记录 | 兼容读取旧协议并只导入收藏；新协议阻止旧客户端继续写入，取消收藏传播因果证据并遵循本机历史保留策略 |

## 空闲资源控制

| 路径 | 当前策略与边界 |
| --- | --- |
| 同步发布 | 固定导出收藏的文字、URL 和原始剪贴板图片，以及设置、删除/取消收藏证据和加密凭据 replica。普通历史和仅置顶项不上传；范围外复制只确认截止时间内的冗余 outbox，不推进 revision，收藏后再从本地数据导出。不可用载荷的待办继续保留。 |
| 容量盘点 | 稳定观察五分钟内复用；完整盘点使用不可变 revision 的容量索引，目录身份或修改时间变化时重新统计，每三十分钟重新测量以容纳原地修复。索引仅用于容量，不作为副本校验或删除依据。发布容量增量只统计本次快照与 manifest，不遍历本机全部历史。 |
| 历史回收 | 有发布台账证明的本机 prepared / superseded 快照在稳定周期也回收；每轮最多十六个、五十毫秒软预算。旧协议目录另按每批三十二个、五十毫秒软预算推进游标，完整一圈后五分钟复查，manifest 变化后重新检查。无台账目录只有满足下节全部因果覆盖条件才回收；当前发布、不确定发布、未知目录和未覆盖内容保留。单次文件系统调用不保证在预算内完成。 |
| 凭据回声 | 已加载且可用的相同云端值不重复解密；旧设置明文擦除在凭据 Actor 上执行，成功后进程内跳过重复读盘，失败允许重试。启动、值变化、删除及故障恢复保留加载路径。 |
| 剪贴板采样 | 仅在 changeCount 变化且成功取得快照时查询前台应用。暂停后停止周期定时器，恢复时重置采样游标，避免补录暂停期间的内容。 |

## 收藏同步、占用统计与升级

- 同步范围固定为仅收藏；旧设置中的 `全部历史`、`仅收藏与置顶` 及容量档位兼容读取并规范化，不能恢复旧上传范围或容量限制。仅置顶而未收藏的记录始终只留在本机。文件、文件夹和图片文件路径继续不受同步支持。
- 不再按应用内同步配额淘汰收藏或暂停图片上传，也不再因旧单图 64 MiB 阈值静默跳过收藏图片。界面固定显示目录已用空间，单位 `MB`；该数字包括快照、设置、加密凭据、协议证据及等待安全回收的历史文件，不等于收藏内容大小，也不是整个 Apple 账户的剩余空间。Apple 账户空间和文件系统错误仍可能使传输失败。
- 协议升级为版本 2，保留版本 1 快照读取兼容；旧客户端发现新版协议后不能继续上传普通历史。所有参与写入的设备均需升级，版本不兼容提示不能通过改回协议版本绕过。
- 升级后新快照不包含普通历史；新设备不会导入旧快照的普通项。取消收藏在同步中保留因果证据，迟到旧收藏不能恢复已取消的状态，再次收藏使用新时钟重新参与同步；取消后的本地记录遵循普通历史保留上限，置顶与仍收藏项继续受保护。即使普通项被本机淘汰，取消收藏证据仍持久保存。
- 远端取消收藏与再次收藏先完成本轮字段合并，再统一裁剪普通历史，避免中途删除本机较新的标签或置顶时钟。快照或整轮同步的载荷缺失、损坏或操作取消时暂缓裁剪，待完整重试成功后恢复历史上限与载荷回收。
- 本机完整校验的旧当前快照加入发布台账后回收。无台账的旧 revision 仅在严格识别协议目录、版本小于本机当前版本，并证明全部旧收藏已由有效收藏、删除标记或取消收藏时钟覆盖后回收；不完整、未知文件或冲突证据保留。普通内容对象仍需满足既有无引用观察保护期（默认 24 小时），不能通过立即删除共享对象跳过多设备安全约束。
- 删除共享内容对象前，还须证明所有保留的历史 revision 具有完整协议三文件与一致身份，读取其中内容引用；不完整、尚未下载或超过验证预算时暂停对象回收，防止迟到的收藏证据引用已删除对象。
- 外机仍在使用的旧快照，需等待该设备升级并完成发布，或由用户显式移除设备后才可回收；离线设备和未知目录不能因占用空间而被自动删除。因此升级不会立即将已有目录缩减为当前收藏的大小，界面仍显示待回收文件实际占用。

## 协议与数据边界

- manifest schema、内容寻址目录和 SQLite schema 保持兼容；现有 UUID 快照及 schema 1 升级路径继续兼容。收藏专用写入协议与旧版本读取边界见上节，各设备需升级后继续写入。
- 删除标记在当前 generation 持续占用少量元数据。文件传输没有可靠的完整成员名单和全局送达确认，因此无法安全地仅按年龄或可见设备回执清除删除证据。
- 所有者只自动恢复可证明的祖先或等价发布。不同设备、未经重置授权的代际、相同 revision 不同内容、不可比较向量及损坏证据均不能自动选边。
- 暂时缺失的文件保留为下载等待；已到达但摘要不符的数据保持失败且不确认 receipt。完整本地内容可修复共享对象。
- 本机设置和剪贴板仍可独立使用；云端发布与本地确认分开验证，失败或取消不能以未发布的草稿确认 outbox。

## 自动化测试结构

固定场景为 `SYNC-CONVERGENCE-001`、`SYNC-RECOVERY-001`、`SYNC-DELETE-001`、`SYNC-SCHEDULE-001`、`SYNC-IDLE-PERF-001`、`SYNC-FAVORITES-001` 和 `SYNC-STORAGE-001`，操作及通过标准见 [人工验证清单](manual-verification.md#同步回归)。剪贴板轮询关联 `CLIPBOARD-IDLE-001`；登录项另见 `LOGIN-ITEM-001`。

`Tests/MacToolsCoreTests/SyncConvergenceTests.swift` 在一台 Mac 上运行两套独立的真实 SQLite、载荷目录、云端视图及生产 `DriveSyncCycleRunner`。网络替身只决定文件何时、以何种顺序到达，不替代数据库、合并、快照校验和发布逻辑。全部数据为临时目录中的合成夹具，不访问实际剪贴板或 iCloud 账户。

| 测试组 | 验证内容 |
| --- | --- |
| 双端收敛 | 独立新增、同时复制同内容、收藏/置顶/标签和设置并发修改；双方数据相同，稳定后 revision 不再增长 |
| 传输故障 | manifest 先到、快照先到、对象迟到、重复和旧版本重放、损坏对象隔离及修复、PNG 逐字节校验 |
| 持久化恢复 | 重新打开磁盘数据库和 runner；发布前失败、指针已写但确认前失败、唯一迟到旧指针、发布中出现更高本机版本 |
| 删除与成员 | 离线删除、双方同时删除、全新第三个数据库读取旧副本、目录暂时不可见、重置代际和移除设备后的向量单调性 |
| 缓存与容量 | 内容迟到后下一周期恢复、稳定周期复用观察、快照清理后容量与真实文件盘点一致 |
| 收藏边界与旧数据 | 旧设置规范化、普通/仅置顶项不导出导入、取消收藏与迟到副本、本机历史限额及载荷回收、裁剪后取消证据持久化、再次收藏、版本 1 读取与版本 2 写入、已证明旧目录回收与未证明目录保留及迟到收藏引用保护 |
| 无限额与占用展示 | 合成占用超过旧配额仍上传收藏图片；占用固定 `MB` 且不显示普通历史、容量分母或容量选择器 |
| 调度 | `ICloudSyncSchedulingTests` 使用真实平台协调器和手动推进的调度器，保存全部排队定时器，验证相同配置及远端配置变化均不终止后台周期，主动同步仅保留最新定时链，排队重置不会被普通同步取消 |

另有 12 个固定种子，每个执行 24 次复制/保护状态操作，穿插离线、延迟队列、乱序交付和数据库重启，共 288 次操作；最终检查内容、记录 ID、收藏与置顶状态，并继续运行空闲周期验证停止发布。测试不使用随机休眠，也不要求两台设备配合。

底层 `DriveSyncStoreTests`、`SyncLocalRepositoryTests`、`SyncManifestConflictResolverTests`、`SyncSnapshotPublicationLedgerTests`、凭据同步测试及平台文件协调/进程锁测试继续覆盖兼容读取、摘要校验、原子确认、凭据保护与并发边界。

## 单机执行

```sh
# 双设备故障、收敛与真实平台调度
swift test --filter 'SyncConvergenceTests|ICloudSyncSchedulingTests'

# 同步与持久化的聚焦回归
swift test --filter 'FavoriteOnlySyncTests|DriveSync|SyncLocalRepository|SyncManifestConflictResolver|SyncSnapshotPublicationLedger|CredentialSyncEngine|ClipboardRepository'

# 空闲资源、凭据回声及暂停恢复
swift test --filter 'DriveSyncPerformanceTests|ClipboardSnapshotSamplerTests|CredentialAccessCoordinatorTests|CredentialRuntimeUpdatePolicyTests'

# 完整验证与严格并发构建
swift test --parallel --num-workers 4
swift build --product MacTools -Xswiftc -strict-concurrency=complete -Xswiftc -warn-concurrency

# 隔离身份的开发包构建
MACOS_SIGNING_MODE=development scripts/package_app.sh
```

## 验证边界

自动化覆盖应用能控制的同步协议、持久化、重试、目录乱序及调度；Foundation 平台测试使用本地临时文件。它们不能证明 Apple 服务端送达时延、账户状态或真实 `NSFileVersion` 冲突分发行为。真实 iCloud 端到端行为的补充检查见 [人工验证清单](manual-verification.md)，不作为日常协议回归依赖。
